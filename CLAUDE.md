# CLAUDE.md — scuttle-dev

## What this is
A Laravel **library package** (not an app) serving the scuttle.dev single-page
site (plus legal PDFs, vCard, QR codes, SEO files) inside a host app via
host-based routing.

## Constraints
- Host has no PHP/Composer. Run package commands via a one-off Docker image
  (`docker run --rm -v "$PWD":/app -w /app composer:2 ...`) or the host app's
  `app` container once installed.
- Distribution is GitHub VCS + git tags only. No Packagist.
- Versioned: change behaviour → bump tag (`vX.Y.Z`) → bump `spdotdev/scuttle-dev` in the host app's own `composer.lock`, commit + push (never run a bare `composer update` directly on the production server — that's invisible to the committed lock and gets silently reverted by the next unrelated deploy).

## Marketing rules
Read `docs/marketing-rules.md` before writing or changing any page text, product, case study or call to action. It is Stas's list of what never goes on the site (zeros, overconfidence, client traces, old scare facts) and what always does (open prices, straight answers, what a product stands for). Add his new rules there with the date.

## Layout
- `src/ScuttleDevServiceProvider.php` — auto-discovered; loads routes + views, publishes config/assets.
- `routes/web.php` — `Route::domain(config('scuttle-dev.domain'))` group: `/`, `/pricing`, `/legacy-health-check`, `/products/{slug}`, `/case-studies/phalcon-to-laravel`, `/privacy`, plus `/robots.txt` + `/sitemap.xml` at root.
- `src/Posts.php` (news articles, each written to sell one service, `/news`, `/news/{slug}`, 301 from `/blog`), `src/Projects.php` (open source and own products, `/projects`, `/projects/{slug}`, `/projects/{slug}/docs` rendered by `project-docs.blade.php` as a docs site with nav, content and on-this-page). `work.blade.php` (`/work`: the twelve deliverables), `cases.blade.php` (`/case-studies` index), `company.blade.php` (`/company`, careers live inside it, never in the menu). Services live at `/services/{slug}`; `/products/{slug}` redirects 301. Sectors are a home block only, not a menu item (GitHub issue #1 for project tags per sector).
- Articles from sd-cms: `Posts::all()` returns the published `cms_articles` rows for site `scuttle` (written over the sd-cms MCP server at plan.scuttle.dev/mcp/cms, reviewed in the admin panel) ahead of the built-in news in `Posts::builtIn()`; a row with the same slug replaces the built-in one; `sells` becomes `products` and `sells`. sd-cms is an optional sibling in the host, never a dependency: `Posts::fromCms()` checks the class and the table and returns nothing in the package tests. The sitemap route appends those articles to `public/sitemap.xml`.
- No tracking today (Stas, 2026-10-30): `SCUTTLE_GA_ID` is empty on d051, so no analytics script and no banner exist on the live site; the privacy statement says so and promises consent first if statistics are ever added. The banner code stays dormant for that day (only with `SCUTTLE_GA_ID` set; the script loads after Agree and never sits in the HTML; Deny is remembered). Own visitor statistics and a heat map in an admin panel are GitHub issue #5; adding them means a consent step and a new privacy paragraph first.
- `privacy.blade.php` is one full statement in both languages (English default, Dutch through the switch, keys `pv_*`), processors DigitalOcean, Google (mail, backups) and Anthropic (Claude for the lead tooling: summaries of public company information and first email drafts, reviewed before sending); Gemini is no longer named.
- `src/Cases.php` — the case studies (one anonymized client case, three own products), rendered by `case-study.blade.php` at `/case-studies/{slug}` and in the home carousel. `src/Http/Controllers/ContactController.php` + `src/Mail/ContactMessage.php` — the contact form on `/contact` (POST `/contact`, throttle 6 a minute, honeypot plus a signed 3-second minimum, Cloudflare Turnstile when `SCUTTLE_TURNSTILE_SITE_KEY` and `SCUTTLE_TURNSTILE_SECRET` are set in the host's .env, mail to `SCUTTLE_CONTACT_TO`). `/scuttle.vcf` serves the vCard as text/vcard; `public/qr/scuttle-vcard.svg` is a QR code that carries the vCard itself (rebuild both with the script in the commit history of 2026-10-24 or by hand: vCard 3.0, CRLF, folded at 75 bytes, base64 photo).
- `src/Catalog.php` — the 12 products in three groups (Assess, Build, Run): names, leads, prices, features, steps. One source for the products mega menu, the home cards and tiles, the pricing page, the product pages and the footer. Prices: Health Check EUR 1,080 (12 h), Architecture Review EUR 1,440 (16 h), security quick scan EUR 720 (8 h), Maintenance Retainer from EUR 720 a month (8 h), everything else quoted per step at EUR 90 per hour excl. VAT; the pricing page shows two blocks of four. The home page shows the twelve once, as the illustrated tiles under "What I build" (the three list cards that repeated them were removed on 2026-10-30, Stas: "list items should not be on the homepage"); their `.c.g` CSS went with them. Plan cards (`pricing.blade.php`, `.plan`): label, title, amount with a unit line under it ("per hour", "fixed, 12 hours"), text, rule, bullets, button; the bullets row takes the spare height so amounts line up across a row and every button is full width at the bottom; "excl. VAT" is said once per block in its header, not per card; one "Recommended" badge per block (Projects in steps, Health Check), the test counts two. Every product carries its own closing call to action (`cta`). Phone rules for the hero (ported from splotnikov-dev on 2026-10-30, keep both sites the same): the `.cmd` line under the buttons holds its parts in `<span>`s inside the `<b>` (EN in the view, NL in the string map, HTML allowed there); a CSS `::before` draws the " · " between them, and under 600 px every part gets its own line; the terminal window (`.shot`) under 980 px has `grid-template-rows:auto minmax(0,1fr)` so the chip row keeps its 35 px before the log has typed anything (without it the two auto rows share the 640 px and the chips stretch to 240 px); the log (`.log`) under 600 px is 12 px with wrapping allowed inside a line. The hero title keeps a space before its `<br>` (EN in the view, NL in the string map) because under 600 px the break is hidden and the browser balances the title into three lines; without the space the two halves glue together. The Health Check keeps its own address (`route` key) and renders through the same `product` view. Adding a product: add it here and to `public/sitemap.xml`; the tests check both.
  Also `/mail/signature-logo.png`, the small logo in the CRM mail signature (white circle, 96 px), routed so it needs no asset publish on the server.
- `src/Http/Controllers/SiteController.php`: renders `scuttle::site` and serves `robots.txt` / `sitemap.xml` straight from the package's `public/`.
- `resources/views/layout.blade.php` — shared shell (nav with the Products mega menu, EN/NL switch on every page, theme button, dark footer block, Dutch strings for the shell); every page extends it. `resources/views/site.blade.php` — the home page (light first, grey plates, Geist, logo 37 "layered squares", decrypt headline, belts, 12 tiles with the line illustrations from `partials/illus.blade.php`); its Dutch strings are pushed into the `nl` stack. `product.blade.php` renders every catalog product, `pricing.blade.php` the pricing page. `case-study` and `privacy` use the `.page` article styles. Every page is switchable to Dutch, see below.
- `public/site.css` + `public/site.js` — the only stylesheet and script. Accent token `--acc` (Claude orange `#CF5A26` light, `#E3835E` dark since v0.3.0; the comparison with indigo and grey is `design/drafts/accent-options.png`). `public/logo.svg` (wide mark), `public/icon.svg` (square mark, source of the favicons); regenerate every logo asset in a new colour with `design/make-logo.sh '<accent>' '<accent light>'` (needs rsvg-convert and ImageMagick). `public/portrait.jpg`, `public/og-image.png`. Logo and theme drafts live in `design/drafts/`.
- The demo panel on the home page (`#demo`) is interactive: the sidebar buttons in `site.blade.php` (data-k) select an entry of the `D` object in `site.js` (automation runs with a typed log, report pages with two readable pages and the rest blurred as confidential, anonymized cases with numbers). Runs and reports are examples with made-up names; the cases are anonymized real work, the cost-saving one is a worked example with illustrative numbers and says so. Panel content is English only.
- Every page is switchable to Dutch (since v0.6.0): the EN/NL switch sits in the bar on every page, every visible sentence carries `data-i="<key>"` and the page pushes its Dutch map into the `nl` stack (`Object.assign(window.SCUTTLE_NL.t, {...})`); data-driven pages build the map from the `nl` arrays in `Catalog` (`Catalog::nl($p)`), `Cases`, `Projects` and `Posts` and emit it with `@json`. Key prefixes per page: `pr_` pricing, `p_` and `ax_` product pages, `wk_` work, `cp_` company, `ctp_` contact, `csi_`/`csp_` case studies, `pj_`/`pjp_`/`pjd_` projects, `bl_`/`blp_` news; the shell and the home page keep their short keys. `site.js` swaps innerHTML, so an element with an svg or a route() href gets a `<span data-i>` around its text, and inline links inside a Dutch string use plain paths. News article bodies and project documentation stay English (the Dutch page says so in one line). `test_every_page_is_translatable` checks every page: switch present, a push block, at least 8 own keys, a Dutch string for every key. On a switch the right side of the bar stays put (`nav.top .cta` has a fixed min-width); the links keep one 22 px gap and re-centre, so they slide by a pixel or two (v0.7.7 dropped the per-link width reservation, which made the gaps uneven).
- The Chamber of Commerce link is the company's own register page, `https://www.kvk.nl/zoeken/#/96040947000061394009/` (the search URL with `?q=` opened an empty search).
- Theme: three-way control System / Light / Dark (`.seg.th`, System default; dark tokens apply through `prefers-color-scheme` when nothing is chosen and through `[data-theme="dark"]` when chosen).
- Hero command line in `site.blade.php` (`data-i="cmd_b"`, EN and the NL string) names the latest PHP security release (8.4.26 → 8.4.27, 21 Oct 2026, from php.net). Refresh it at every PHP security release; the test pins the current text.
- `tests/Feature/PreviewDumpTest.php` writes every page as static HTML when `SCUTTLE_DUMP=<dir>` is set (skipped otherwise), so the theme can be screenshotted without a PHP host.
- `config/scuttle-dev.php` — `domain` via `SCUTTLE_DOMAIN`.
- `public/` — all site assets (images, qr/, legal/*.pdf, vCard, manifest, robots, sitemap) published to the host's `public/vendor/scuttle`.
- `.env.example` — documents env vars this package reads (currently just `SCUTTLE_DOMAIN`); all have safe defaults, so it's optional, not required for install. Copy relevant lines into the host app's own `.env`.

## Head, fonts and contrast (v0.7.12, 2026-10-30)
- `layout.blade.php` builds the title and description for every page: title with the brand suffix when it fits in 62 characters, else the bare title cut at a word boundary under 70; description cut at a sentence end (not after "excl.") or a word boundary under 160. Every inner page also gets a BreadcrumbList; service pages a Service block, news articles an Article block (`'@'.'context'` in the views, because Blade reads a literal `@context` as a directive). `og:type` defaults to website, news articles say article. Test: `test_search_snippets_fit_and_structured_data_is_valid`.
- Geist and Geist Mono are self-hosted in `public/fonts/` (variable woff2, latin and latin-ext, SIL OFL licence next to them); `site.css` starts with the `@font-face` rules and the layout preloads the two latin files. No request goes to Google Fonts any more.
- Orange badges and the contact buttons use a deeper orange with white text in light mode and dark text on the lighter orange in dark mode (contrast over 4.5:1). The decrypt headline pins its box height while it settles so nothing below it jumps. Status of every page: `docs/IMPROVEMENT-STATUS.md`.

## Deploy (set 2026-10-13, HARD RULE, user decision)
Production on d051 always runs the latest `main` of this project. When the user asks for a change and it is merged to main, deploy it yourself right away, without asking: push or merge, watch CI and the deploy to the end, and check the server runs that commit. If this project uses tags, deploy the latest tag every time. Anything not in main is local testing and is never deployed. A failing deploy is reported first as broken, with what it blocks. Never open PRs unless asked.
